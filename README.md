# Генератор счетов для лицензий amoCRM

Самостоятельный сервис для формирования счетов-оферт по лицензиям amoCRM. Работает через внешнюю OAuth-интеграцию amoCRM и не требует платного виджета «Документы 2.0» или приватного JavaScript-виджета.

## Что умеет сервис

- запускает генерацию автоматически на выбранном этапе воронки или вручную через этап `Перегенерировать счёт`;
- включает в счёт только товары, отмеченные флагом `Лицензия amoCRM`, и исключает услуги;
- получает реквизиты покупателя из привязанной к сделке компании;
- использует зашитые реквизиты сублицензиара и данные партнёрского соглашения с amoCRM;
- создаёт DOCX и PDF, загружает PDF в раздел Media сделки и оставляет примечание с номером актуального счёта;
- нумерует счета в формате `ЛЦ-АМ-{ID сделки}-{глобальный шестизначный счётчик}`;
- не расходует новый номер при повторном запуске без изменений;
- при изменении реквизитов, цены, количества или состава лицензий создаёт новую ревизию и сохраняет прежний файл в истории;
- при неполных или некорректных реквизитах не выпускает PDF и оставляет менеджеру понятное примечание;
- шифрует OAuth-токены в PostgreSQL и ограничивает частоту запросов к API amoCRM.

Сервис не отправляет счёт клиенту автоматически. После генерации менеджер самостоятельно берёт PDF из сделки и отправляет его клиенту.

## Состав

- `web` — принимает OAuth callback и webhook-запросы от amoCRM;
- `worker` — читает сделку, формирует документ и публикует его в amoCRM;
- `db` — отдельная PostgreSQL для OAuth-токенов, очереди, счётчика и истории ревизий;
- LibreOffice — преобразует сформированный DOCX в PDF.

Все контейнеры запускаются отдельным Docker Compose-стеком. PostgreSQL не публикуется наружу, а HTTP-сервис доступен локально на VPS через `127.0.0.1:18080` для подключения к Nginx или Caddy.

## Требования

- VPS с Docker Engine и Docker Compose;
- отдельный поддомен с HTTPS, например `https://invoices.example.ru`;
- внешняя интеграция в amoCRM с Client ID и Client Secret;
- числовой ID поля-флага `Лицензия amoCRM` в каталоге товаров.

## Установка на VPS

```bash
git clone https://github.com/sonicgithub86/invoice-amocrm.git
cd invoice-amocrm/invoice-service
cp deploy/invoice-service.env.example deploy/invoice-service.env
cp deploy/postgres.env.example deploy/postgres.env
```

Заполните оба env-файла. Важные значения:

- `APP_BASE_URL` — полный публичный адрес с `https://`, без завершающего `/`;
- `DATABASE_PASSWORD` и `POSTGRES_PASSWORD` — один и тот же новый пароль;
- `AMO_CLIENT_ID` и `AMO_CLIENT_SECRET` — данные внешней интеграции amoCRM;
- `AMO_PRODUCT_LICENSE_FIELD_ID` — ID флага в каталоге товаров;
- `AMO_CREDENTIAL_KEY_V1` — отдельный 32-байтовый ключ в Base64;
- `OPERATOR_ACCESS_TOKEN` — длинный случайный секрет администратора.

Примеры генерации секретов:

```bash
openssl rand -base64 32
openssl rand -hex 32
```

Запустите сервис и примените миграции:

```bash
docker compose up --build -d db web worker
docker compose exec web php bin/console migrate
```

Настройте reverse proxy с публичного HTTPS-поддомена на `http://127.0.0.1:18080`. Проверка доступности:

```bash
curl -fsS https://invoices.example.ru/healthz
```

Ожидаемый ответ: `{"status":"ok"}`.

## Подключение amoCRM

1. Создайте в amoCRM внешнюю интеграцию.
2. Укажите Redirect URI: `https://ваш-поддомен/oauth/callback`.
3. Запишите Client ID и Client Secret в `deploy/invoice-service.env`.
4. Создайте в каталоге `Товары` поле-флаг `Лицензия amoCRM` и запишите его ID в `AMO_PRODUCT_LICENSE_FIELD_ID`.
5. Отметьте этим флагом только карточки лицензий amoCRM.
6. Перезапустите контейнеры после изменения env-файла.
7. Получите ссылку авторизации:

```bash
docker compose exec web php bin/console oauth-url
```

8. Откройте ссылку в браузере и разрешите доступ к аккаунту amoCRM.
9. После OAuth сервис покажет две уникальные webhook-ссылки: `automatic` и `rerun`. Сохраните их — ссылки содержат секрет доступа.

Подробная инструкция и используемые ID полей находятся в [документации по настройке amoCRM](invoice-service/docs/AMOCRM_SETUP.md).

## Настройка воронки

В Digital Pipeline добавьте два действия `API → Отправить webhook`:

1. На этапе автоматического выставления счёта используйте ссылку `automatic`.
2. На отдельном этапе `Перегенерировать счёт` используйте ссылку `rerun`.

amoCRM должна передавать ID сделки. Сервис понимает поле `lead_id` и стандартные структуры webhook для сделок.

## Порядок использования менеджером

1. Привязать к сделке компанию-покупателя и заполнить её юридические и банковские реквизиты.
2. Добавить в сделку нужные товары-лицензии amoCRM с корректной ценой и целым количеством.
3. Перевести сделку на настроенный этап автоматической генерации или на этап `Перегенерировать счёт`.
4. Дождаться PDF в разделе Media и примечания с номером актуального счёта.
5. Проверить документ и отправить его клиенту вручную.

Если исходные данные не изменились, повторный запуск сохранит прежний номер. Если реквизиты или лицензии изменились, сервис выпустит новый счёт с новым номером, а старый останется в истории.

## Обслуживание

```bash
# состояние контейнеров
docker compose ps

# журналы приложения
docker compose logs -f web worker

# ручное обновление OAuth-токенов
docker compose exec worker php bin/console refresh-oauth

# применение обновлений проекта
git pull
docker compose up --build -d
docker compose exec web php bin/console migrate
```

Не публикуйте `deploy/invoice-service.env`, `deploy/postgres.env`, OAuth-токены, webhook-ссылки и созданные документы. Эти файлы исключены из Git.

## Разработка и проверка

```bash
cd invoice-service
composer install
composer qa
docker compose config --no-interpolate --quiet
```

Основной код сервиса находится в каталоге [`invoice-service`](invoice-service/).
